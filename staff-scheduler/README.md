# 班表 — 餐饮排班 / 工时 / 薪资自动化系统

单文件 Web 应用（`index.html`），零依赖、无需构建。为餐饮门店解决老板每月最痛的两件事：**排班**与**算薪水**（兼职时薪、加班、请假）。

分**管理端**（老板 / 店长）与**员工端**两套界面，界面语言支持**中文 / English / Bahasa Melayu**。

## 运行

直接用浏览器打开 `staff-scheduler/index.html` 即可。

若浏览器限制了 `file://` 的本地存储（数据无法保存），用本地服务器打开：

```bash
py -m http.server 8123
```

然后访问 http://localhost:8123/staff-scheduler/index.html

数据保存在浏览器 localStorage（key: `banbiao.v1`），不上传任何服务器。设置页可导出 / 导入 JSON 备份。

## 两个端

左下角「切换到员工端 ›」进入员工端，员工端「我的 → 返回管理端」回到管理端。若在设置里填了**管理端密码**，从员工端返回时需要输入（一台平板给全店共用的场景）；留空则不上锁。上次用的是哪个端、哪位员工、哪种语言都会记住。

### 管理端（老板 / 店长）

七个页面，见下表。可以改排班、看全店工资、审批请假。

### 员工端（每位员工只看得到自己）

| 页面 | 作用 |
|------|------|
| 我的班表 | 顶部是今天的班 + **上班/下班打卡**按钮（迟到会提示）；本周工时、本周预估工资；整周班表逐日列出，请假与休息一并显示 |
| 我的工时 | 自己的打卡 vs 排班、迟到次数、缺卡；下面是本周的工资构成明细（正常/加班/小费） |
| 请假 | 自助提交请假申请（自动锁定为本人），实时看到「等待批准 / 已批准 / 已拒绝」，待批的可以撤回 |
| 我的 | 个人资料、时薪、每周上限、可上班时段（只读，改动需找店长）；界面语言与深浅色切换 |

员工端不能修改排班、不能看到别人的工资、不能审批请假。

## 管理端的七个页面

| 页面 | 作用 |
|------|------|
| 总览 | 本周人力成本、人力成本占比（对比目标 %）、排班工时、待办；每日成本柱状图、今日班次、加班预警、待批请假、排班缺口 |
| 排班 | 周视图网格（员工 × 7 天）。拖动班次换人/换天、点击编辑、一键智能排班、复制上周、导出 CSV、打印班表 |
| 工时 | 打卡 vs 排班对比，迟到 / 早退 / 缺卡统计，逐日补录打卡，一键按排班补录 |
| 薪资 | 按周期自动核算正常工时、加班费、小费分配、雇主税；逐人工资单；导出 CSV |
| 员工 | 时薪 / 月薪、可担任岗位（多技能）、每周工时上限、每天可上班时段、在职状态 |
| 请假 | 申请、批准 / 拒绝。批准后自动取消冲突班次，并从自动排班中排除 |
| 设置 | 加班规则、计薪来源、雇主税率、人力成本目标、班次模板、每日用人需求、数据备份 |

## 核心引擎

### 自动排班 `autoSchedule(周一日期)`

按「每日用人需求」（星期几 → 班段 → 岗位人数）逐个填人。候选人必须同时满足：

- 岗位在员工技能列表内
- 当天没有已批准的请假
- 班次时间落在该员工当天的可上班时段内
- 与当天已有班次不重叠
- 加上这个班后不超过该员工的每周工时上限

排序策略：**已排工时占比最低的人优先** → 主岗优先 → 时薪低者优先。排不满的岗位记为「缺口」，在总览与排班页显示。

### 冲突检测 `conflictsOf(班次)`

请假冲突 / 超出可上班时段 / 同日班次重叠 / 超周工时上限 / 岗位技能不符。任一命中，班次上显示红色 `!` 角标。

### 薪资计算 `computePayroll(起, 止)`

1. 逐日取工时：优先实际打卡，缺卡且日期已过按 0 计（可在设置改为「按排班」）
2. 单日先扣双倍工时（可选，默认关）与每日加班（可选，默认关，加州式 8h）
3. 按周汇总，正常工时超过每周门槛（默认 FLSA 40h）的部分转为加班
4. 时薪制：基本 = 正常工时 × 时薪，加班费 = 加班工时 × 时薪 × 倍率（默认 1.5）
5. 月薪制：按周期天数折算，不计加班
6. 小费池按工时分配给**时薪制、非管理岗、且岗位接触客人**的员工（符合 FLSA 对小费池的限制）
7. 雇主总成本 = 应发 × (1 + 雇主税率)，默认 7.65%

## 多语言

`I18N` 里三份等长的词典（`zh` / `en` / `ms`）加一个 `t('key', {vars})`，缺失的键回退中文。除了界面文案，下面这些也跟着语言走：

- 岗位名、班次模板名、请假类型：数据里存的是语言无关的 key（`chef` / `tpl.close` / `annual`），显示时才翻译，所以切换语言不会改动任何数据
- 星期：三套长度（`一` / `周一` / `周一`；`Su` / `Mon` / `Monday`；`Ah` / `Isnin` / `Isnin`），网格表头用中等长度，设置页用完整名
- 日期：中文 `9月6日`，英文 `Sep 6`，马来文 `6 Sep`；「日期 + 星期」的顺序也按语言调整（`9月6日 周日` / `Sunday, Sep 6`）
- 旧版本存的中文枚举（如请假类型「事假」）在加载时自动迁移成 key

语言在管理端「设置」、员工端「我的」、或侧边栏 🌐 按钮里切换，存在 localStorage，与数据备份一起走。

## 数据结构

```js
staff  = { id, n, roles[], pay:'hourly'|'monthly', rate, maxH, avail:{0..6:[起分钟,止分钟]|null}, active, hired, phone, note }
shift  = { id, staffId, date:'YYYY-MM-DD', start:'HH:MM', end, brk, role, tpl, note }
punch  = { id, shiftId, staffId, date, in, out, brk }
timeoff= { id, staffId, from, to, type:'personal'|'sick'|'annual'|'unpaid', reason, status:'pending'|'approved'|'rejected' }
demand = { 0..6: [ { tpl:模板id, need:{ 岗位: 人数 } } ] }
```

## 交互与设计

Apple 设计语言（参考 *Designing Fluid Interfaces*）：

- **弹簧动画**：自写临界阻尼弹簧（damping / response 两个参数），随时可打断，从当前值出发
- **1:1 跟手拖拽**：Pointer Events + 指针捕获，保留抓取偏移；松手时把手势速度交接给弹簧，落点用苹果的动量投影公式
- **数据先落地**：松手瞬间即写入数据并重绘，残影动画只是修饰，后台标签页节流也不会丢操作
- **面板**：移动端底部 sheet 支持下拉关闭（越界橡皮筋 + 速度投影决定去留），桌面端居中弹出
- **材质**：侧边栏 / 顶栏 / 提示条使用 `backdrop-filter` 半透明层，内容从下面滚过
- **无障碍**：`prefers-reduced-motion` / `prefers-reduced-transparency` / `prefers-contrast` 全部适配，深色模式自动跟随系统并可手动切换

## 键盘

`←` / `→` 切换上一周 / 下一周，`T` 回到本周，`Esc` 关闭面板。

## 还没做的

- 真正的账号体系。目前员工端靠「选自己的名字」进入，返回管理端可选密码保护——够一台店内平板用，但不足以让每个员工在自己手机上登录。要做到那一步需要后端。
- 打卡只存 `HH:MM`，同一分钟内连点两次上班/下班会被当成 0 工时（已做保护，不会算成一整天）。
